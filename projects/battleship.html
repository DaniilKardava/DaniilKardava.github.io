How many ways can ships share a board without colliding?

A board arrangement is determined by choosing a position and orientation for every ship. Checking whether one arrangement is legal is easy: no two ships may occupy the same square. Counting every legal arrangement is much harder because the number of possibilities multiplies rapidly with the size of the board and fleet.

This project approaches that count indirectly. It temporarily allows ships to collide, assigns a penalty to every overlap, and gradually strengthens that penalty. Measurements taken along the way reveal how much of the original space remains once only collision-free boards are allowed.

The idea

Count the easy world, then measure the path to the hard one.

If overlaps are allowed, counting is straightforward: each labeled ship may independently occupy any position that fits on the board. Call this known total Nall. The answer we want, Nlegal, counts only the boards with no collisions.

Give every board x an energy E(x) that measures its overlap. Legal boards have zero energy; collisions produce positive energy. The partition function Z(β) is a weighted count of every board:

Z(β) = Σx exp(−β E(x))

The parameter β is a penalty dial. At β = 0 every board has weight one, so Z(0) = Nall. As β tends to infinity, every positive-energy board is suppressed while every zero-energy board keeps weight one, so Z(∞) = Nlegal.

The average energy under the distribution at β gives the rate at which this weighted count shrinks:

d log Z(β) / dβ = −𝔼β[E]

Integrating that rate from the unrestricted endpoint to the collision-free endpoint gives the desired count:

Nlegal = Nall exp(−∫0∞ 𝔼β[E] dβ)

In practice, the Gibbs sampler draws boards at a sequence of β values. Their energies estimate 𝔼β[E] at each point, and those estimates are used to approximate the integral numerically.

Performance optimization

Profile. Change the data structure. Profile again.

The Python prototype established correctness, but moving the sampler to C++ was only the beginning. I used VTune to follow the hot path through successive revisions; saved gprof snapshots preserve the call counts. The expensive operation was not evaluating one board: it was repeatedly rebuilding a probability distribution over every possible placement.

01 · Find the repeated work

One random draw rebuilt the entire distribution.

The first C++ version stored one Boltzmann weight for each of M candidate placements. Every Gibbs move constructed a new std::discrete_distribution, which normalized the weights and built cumulative sums before returning a single sample. In one preserved pre-redesign profile, that run produced 12,000 calls each to normalization, accumulation, and partial_sum.

Original sampling path · O(M) setup for each draw
M placement weights→Rebuild categorical table→Return one placement
02 · Adapt Walker's sampling idea

Sample weight classes instead of individual placements.

Walker's method suggested replacing one long weighted choice with smaller uniform choices. Here the distribution changes after every move, but the energy is integer-valued, so thousands of placements share only a small number L of distinct weights. I adapted that idea into a dynamic sampler built from energy buckets rather than repeatedly rebuilding a static table over all M placements.

Bucketed sampling path · L is much smaller than M
L energy buckets→Choose a bucket by total weight→Choose an ID uniformly
P(E=e) ∝ |Be| exp(−βe),   P(id | E=e) = 1 / |Be|

Why it is correctEvery placement in bucket Be has the same weight exp(−βe). Choosing the bucket by its total mass and then choosing uniformly inside it gives each placement exactly that Boltzmann probability.

Why it is fastThe sampler scans L energy levels and then draws from one vector in constant time. A reverse index supports constant-time swap-and-pop moves when a placement changes buckets.

03 · Follow the hotspot

Each improvement revealed the next bottleneck.

After the categorical table disappeared, profiles shifted into the code that maintained the buckets. The remaining commits form a clear optimization loop: measure a hot path, exploit the sampler's local structure, and measure again.

Storage

Removed the tensor dependency, flattened the grid, and passed ship state by reference. The accompanying commit recorded the rewritten implementation as roughly three times faster than the preceding C++ version.

Deduplication

Removed an unordered_set from the marginal update path. The recorded 100,000-step benchmark fell from 2.5 to 1.8 seconds—a 28% reduction.

Local movement

Accumulated all energy changes first, then moved each affected placement between buckets once. This eliminated the redundant bucket removals and insertions caused when one placement intersected several changed squares.

Cached weights

A saved post-bucket profile exposed about 61.6 million repeated exponential evaluations. Since every bucket shares one weight, the next version cached exp(−βe) once per energy level and removed virtual dispatch from the hot update.

Memory layout

Finally, the vectors of buckets were flattened into contiguous storage, reducing indirection while preserving constant-time membership updates through reverse indices.

This account is reconstructed from the commit history, saved gprof snapshots, benchmark notes, and shell history confirming a VTune session on the C++ executable. The original VTune result directory was not committed, so the page reports only measurements that remain recoverable.

Exact validation

The sampler tracks ground truth.

For three labeled length-2 ships on a 4×4 board, all 13,824 configurations can be enumerated. A fixed-seed run used 4,000 independently initialized samples at each of 25 β values and closely followed the exact Boltzmann expectation.
