Reinforcement learning · Neural networks · Game environments

Building a 2048 agent—twice.

Two versions of the same reinforcement-learning idea: first implement the neural-network machinery from scratch, then use TensorFlow and Keras to train, save, and visualize an agent that reaches the 2048 tile.

  • TensorFlow / Keras
  • Advantage actor–critic
  • Convolutional networks
  • Custom environment
  • Pygame

Why 2048?

Every move changes what will be possible later.

2048 has only four actions—left, right, up, and down—but choosing well requires more than collecting the largest immediate merge. A move rearranges the whole board, a new tile appears at random, and a locally rewarding choice can destroy the structure needed to survive many turns later.

That makes the game a compact reinforcement-learning problem. The agent must learn a policy under randomness, delayed consequences, a changing set of legal moves, and an enormous number of possible board configurations.

board → action → merge reward + new random tile

The project begins below the learning algorithm: it implements the game rules, transition function, rewards, terminal condition, and feature encodings from scratch.

Two implementations

Understand the machinery. Then use the tools.

The two projects share the 2048 environment and actor–critic strategy, but answer different engineering questions.

01 · From scratch

Build the learning stack.

A NumPy/SciPy implementation supplies convolutional and dense layers, forward and backward passes, activation derivatives, weight initialization, Adam and SGD updates, action masking, and the actor–critic learning rule.

02 · With libraries

Scale the experiment.

The TensorFlow/Keras version expresses the policy and value models with standard layers and automatic differentiation, making it practical to train longer, save checkpoints, reload policies, and record complete games.

Shared design

One network chooses. Another judges.

Both implementations use advantage actor–critic. The scratch version exposes how each gradient is constructed and propagated; the library version applies the same division of labor with Keras models and gradient tapes.

State

Each tile is encoded by its power of two, producing an 11-channel 4×4 representation that preserves the board’s spatial structure.

Policy

A convolutional network outputs probabilities for the four directions and samples the agent’s next action.

Value

A second convolutional network predicts return and supplies the advantage signal used to improve the policy.

Mask

Moves that leave the board unchanged receive effectively zero probability, so the agent samples only valid actions.

Reward

Merged tile values provide the learning signal, aligning return with the familiar score accumulated during a game.

Models

In the Keras project, policy and value networks are saved independently so trained checkpoints can be evaluated and visualized later.

Library implementation · training

Learning is noisy, so the trend matters.

The Keras experiment plots episode reward together with a 50-episode rolling mean. Individual games vary because tiles appear randomly, so the smoothed trace makes longer-term improvement easier to distinguish from lucky or unlucky games.

Broader workspace

From fundamentals to applied agents.

The repository also contains CartPole actor–critic implementations, a digit classifier, and experimental trading environments. Together with the paired 2048 builds, they document a progression from implementing the mechanics of neural networks and reinforcement learning to assembling complete agents with modern frameworks.

2048 is the clearest case study because the scratch and library versions make that progression directly comparable while sharing the same environment, representation, and learning objective.
